# 公共契约开发与演进指南

## 边界

`contracts/openapi`、`contracts/proto` 和 `contracts/schema` 是跨进程契约的唯一真源。`contracts/generated` 只保存统一生成命令的输出，禁止手工修改。服务必须把生成 DTO 映射到私有领域模型，不得共享数据库表、ORM 模型或 `internal/` 包。

Java/JDK 不属于本项目工具链。后端与 Go SDK 使用 Go，Portal 与 Web SDK 使用 TypeScript，只有经性能基准证明的独立热路径才考虑 Rust。

## 本地命令

```bash
node scripts/bootstrap-contract-tools.mjs
node scripts/generate-contracts.mjs
node scripts/validate-contracts.mjs
node --test scripts/contracts.test.mjs
```

工具安装在被 Git 忽略的 `.tools/contracts`，不会读取或修改系统 Go。版本、下载地址、摘要和源提交记录在 `contracts/toolchain.lock.json`。

预置 `.tools/contracts` 和 `node_modules` 后可执行严格离线门禁：

```bash
HNB_CONTRACT_TOOLS_OFFLINE=1 node scripts/validate-contracts.mjs
```

离线模式不会下载二进制、安装 Go 工具或运行 `npm ci`，且 Go 生成阶段固定 `GOPROXY=off`；任一缓存缺失或与锁文件不匹配时立即失败。Release Bundle 的组装清单、许可证和审计证据见 `openspec/changes/bootstrap-contracts-events/evidence/supply-chain-report.md`。

## 新增契约

1. 在对应版本目录新增或修改源 Schema。
2. OpenAPI 写操作必须声明 `X-Correlation-ID` 和 `Idempotency-Key`；更新、删除还必须声明 `If-Match`。
3. 事件必须携带 Message ID、Schema Version、Correlation ID 和 Idempotency Key。
4. 只能传递 `SecretReference` 和不可变 Payload Reference，不能加入密码、Token、kubeconfig、私钥或大文件正文。
5. 运行生成命令并评审源 Schema 与生成物差异。
6. 运行统一门禁和自动测试。

## 兼容演进

同一主版本允许：

- 增加可选字段；
- 增加 endpoint、message 或新的可选事件 payload；
- 增加不改变既有语义的 Schema；
- 为 Protobuf 增加未使用字段号。

同一主版本禁止：

- 删除字段或把可选字段改为必选；
- 改变字段类型、格式或既有语义；
- 删除枚举既有值；
- 复用 Protobuf 字段号或字段名；
- 改变 operationId、package 或资源标识含义。

删除 Protobuf 字段时必须保留 `reserved` 字段号和名称。兼容检查以 `origin/main` 为基线；首次引入契约时输出 `compatibility=no-baseline`，合并后不得静默跳过。

## 弃用与主版本升级

1. 先把字段标记为 deprecated，并在文档和遥测中暴露使用情况。
2. 保持兼容读写，提供消费者迁移说明和截止时间。
3. 消费者完成迁移后，在新的 `v2` 目录或 package 中定义破坏性契约。
4. v1 与 v2 并行运行一个批准的迁移窗口。
5. 删除旧版本前保存兼容、消费者和回滚证据。

主版本升级不能通过覆盖 v1 文件实现。OpenAPI 路径/版本、Protobuf package 和 JSON Schema `$id` 必须体现新主版本。

## 生成与回滚

生成先进入临时目录，Go 与 TypeScript 编译成功后才原子替换 `contracts/generated`。失败时保留上一版生成物。

回滚必须同时恢复：

- 源 Schema；
- `toolchain.lock.json` 和 package lock；
- 生成配置；
- 全部 Go/TypeScript 生成物。

不得只回滚生成代码或只回滚 Schema。恢复后必须重新运行统一契约门禁。
