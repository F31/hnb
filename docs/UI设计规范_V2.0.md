# UI / UX 设计规范 V2.0

> 版本：V2.0　|　发布日期：2026-07-28　|　密级：内部
> 本版基于《HNB Web Console 微内核插件化架构设计 V3.6》的落地需求，对 V1.0 通用设计规范进行**抽象与结构化升级**：从"页面级静态规范"演进为"可承载微内核 + 插件化 + 服务端驱动导航"的架构级设计规范。V1.0 中流式布局、三级菜单、i18n、按需加载、风格切换五项能力保留并作为核心主线，本版为每一项补充**架构落地约束**，并新增权限安全边界、多租户上下文治理、缓存与性能治理三章。

## 文档说明

### V1.0 → V2.0 变更对照表

| 维度 | V1.0 | V2.0 |
|---|---|---|
| 规范定位 | 通用页面级 UI/UE 规范 | 微内核 + 插件化架构下的设计规范，前端仅为架构的展示层实现 |

| 缓存与性能治理 | 未涉及 | **新增章节**：L1 / L2 / L3 分层缓存模型，作为"按需加载"能力的性能支撑 |

## 1. 总体设计原则

在 V1.0 七项原则基础上，结合微内核架构补充为 **十二项**：

| 原则 | 说明 |
|---|---|
| 一致性 Consistency | 同一层级、同一语义元素在视觉与交互上保持统一，跨插件、跨语言、跨主题一致 |
| 层级清晰 Clarity | 信息架构扁平化，导航层级最多三级 |
| 性能优先 Performance | 页面、组件、语言包按需加载，首屏渲染优先 |
| 国际化友好 Global-ready | 文案、日期、数字、方向均可本地化，不硬编码语言相关内容 |
| 弹性适配 Responsive | 布局基于流式（Fluid）与栅格系统，适配不同宽度视口 |
| 可主题化 Themeable | 视觉属性全部令牌化，支持浅色 / 深色及品牌主题动态切换 |
| 可访问性 Accessibility | 满足 WCAG 2.1 AA 级对比度与键盘操作要求 |
| **导航单一来源**（新增） | 后端是菜单、路由、权限配置的唯一权威来源，前端不做兜底生成 |
| **零耦合**（新增） | 插件之间禁止直接引用，只能通过 Shell EventBus、统一 API Client 和公共契约通信 |
| **拒绝默认放行**（新增） | 菜单、路由、组件在权限 / 插件 / 上下文未就绪时默认不展示，禁止因异常而"降级放行" |
| **配置驱动扩展**（新增） | 新增、排序、隐藏、分组、租户授权通过配置与注册完成，原则上不修改核心壳（Shell）代码 |
| **上下文原子性**（新增） | 租户 / 空间 / 环境切换必须整体生效或整体回滚，禁止出现半新半旧的界面状态 |

## 2. 架构分层与规范定位

将设计规范映射到微内核架构的三层，避免"设计只管页面、架构只管代码"的脱节：

```text
┌─────────────────────────────────────────────────────────┐
│  Shell 层（本规范第 3 / 8 / 11 / 12 / 13 / 14 章约束对象） │
│  Auth / Layout / Context / Navigation / Router /          │
│  Plugin Manager / Event Bus / Permission Store            │
├─────────────────────────────────────────────────────────┤
│  插件层（本规范第 4 / 5 / 6 章约束对象）                    │
│  Dashboard / Application / Container / Resource /          │
│  Service（含 MySQL / PostgreSQL / Redis 等子插件）/ AI     │
├─────────────────────────────────────────────────────────┤
│  服务端控制面（本规范第 7 / 9 / 10 章约束对象）             │
│  Navigation Service（L1/L2/L3）/ Plugin Registry /         │
│  IAM·RBAC / Capability / License                          │
└─────────────────────────────────────────────────────────┘
```

**【必须】** 任何 UI 需求评审需先明确其归属层级：属于 Shell（全局壳能力）还是插件（业务能力），二者的设计约束、发布节奏与权限边界不同。

## 3. 布局系统：流式布局

### 3.1 流式布局原则（沿用 V1.0，补充壳层职责）

**【必须】** 页面主容器宽度使用 `max-width + 100%` 组合，间距使用相对单位；由 Shell 的 **Layout Manager** 统一管理顶部导航、侧边栏、内容区骨架，插件只负责内容区内部渲染，不得重新定义全局布局容器。

### 3.2 响应式断点与栅格

| 断点 | 视口范围 | 栅格列数 | 外边距 | 侧边栏行为 |
|---|---|---|---|---|
| xs | < 576px | 4 列 | 16px | 隐藏，改为抽屉导航 |
| sm | 576–767px | 4 列 | 24px | 隐藏，改为抽屉导航 |
| md | 768–1023px | 8 列 | 32px | 默认收起为图标态 |
| lg | 1024–1439px | 12 列 | 40px | 默认展开 |
| xl | 1440–1919px | 12 列 | 64px | 默认展开 |
| xxl | ≥ 1920px | 12 列（内容居中） | ≥ 96px | 默认展开，内容不铺满超宽屏 |

**【建议】** 侧边栏折叠 / 展开状态与当前 tenant/space 上下文解耦，属于用户 UI 偏好，不随导航数据刷新而重置。

### 3.3 间距基准

延用 8px 基准网格（4 / 8 / 12 / 16 / 24 / 32 / 48 / 64），插件内部组件间距必须复用 Shell 提供的间距 Token（见第 8 章），不得在插件内部重新定义间距常量。

## 4. 导航体系：不超过三级菜单（服务端驱动）

### 4.1 核心变更：导航单一来源

**【必须】** 前端不再维护本地菜单 Manifest（如 `plugin-manifest.json`）作为菜单来源或失败兜底。菜单树由后端 **Navigation Service** 联合以下数据实时计算并通过唯一接口下发：

```text
GET /api/v1/navigation/menus
→ 输入：当前用户 / 角色 / 租户 / 空间 / 已启用插件 / License / Feature Flag
→ 输出：menus（菜单树）+ routes（路由映射）+ plugins（可用插件清单）
```

前端 **Navigation Manager** 只负责：请求、缓存、版本比对与降级展示，不做权限裁剪。

### 4.2 三级菜单的数据模型约束

| 层级 | 数据实体 | 说明 |
|---|---|---|
| 一级 | `navigation_menus`（`parent_id = null`） | 全局业务域，对应 Shell 顶部导航或侧边栏一级分组 |
| 二级 | `navigation_menus`（`parent_id` 指向一级） | 功能分类，可折叠 |
| 三级 | `navigation_menus`（`parent_id` 指向二级） | 叶子节点，必须绑定唯一 `route_name` |

**【必须】** 菜单表的 `parent_id` 允许更深层级存储（便于未来扩展），但**展示层与产品策略强制约束不超过三级**；超出三级的业务诉求必须通过页内 Tab、筛选器或详情抽屉承载，禁止在导航树中继续下钻第四级。

**【必须】** 发布前校验规则（对应后端注册事务）：

- `menu.parent_id` 存在且无循环引用；
- `menu.route_name` 指向有效路由，路由再指向 `plugin_id + component_key`；
- 菜单、路由不允许直接下发可执行脚本或组件表达式，只能引用受信标识符；
- 核心菜单 / 核心路由命名空间不得被第三方插件覆盖。

### 4.3 面包屑与菜单状态

沿用 V1.0 面包屑映射一 → 二 → 三级路径的规则；状态定义（默认 / 悬停 / 选中 / 禁用）保持不变，新增：

**【必须】** 禁用态需区分两种语义并给出不同提示：① 权限不足（提示"暂无权限，请联系管理员"）；② 插件未启用 / License 未开通（提示"该能力未开通，前往应用市场了解"）。二者视觉均为灰态，但引导操作不同。

### 4.4 默认拒绝原则在导航中的体现

**【必须】** 菜单 API 未返回、权限未加载完成或插件状态未知时，对应菜单项**不渲染**（而非渲染后置灰），避免因加载时序问题短暂闪现未授权入口。

## 5. 国际化 i18n 规范（插件级语言包）

### 5.1 语言与文案管理（沿用 V1.0）

支持 `zh-CN`（默认）/ `en-US`，架构层面预留多语言横向扩展能力；文案统一收敛为 key-value 语言包，禁止硬编码。

### 5.2 新增：插件级语言包合并机制

**【必须】** 语言资源随插件**按需加载**，不随 Shell 主包一次性下发：

```text
插件目录约定：
plugins/<plugin-name>/locales/zh-CN.json
plugins/<plugin-name>/locales/en-US.json

加载时机：
PluginLoader 解析 Bundle → 注册组件 → 合并 locales 到全局 i18n Store
（与 onActivate 生命周期同批执行，禁止延后到组件渲染中途才加载导致文案闪烁为 key）
```

**【必须】** 插件语言包 key 必须加插件命名空间前缀（如 `service.mysql.form.host`），避免跨插件 key 冲突覆盖 Shell 或其他插件文案。

**【建议】** Shell 全局通用词汇（"确定""取消""保存""加载中"等）收敛到 Shell 公共语言包，插件通过 `packages/ui-kit` 复用，不重复翻译。

### 5.3 界面弹性与本地化格式（沿用 V1.0）

**【必须】** 按钮、标签、菜单项容器宽度使用 `min-width + 内容自适应`，避免英文文案（通常比中文长 30%–100%）溢出截断。

| 内容类型 | 本地化要求 |
|---|---|
| 日期 | zh-CN：`2026年7月28日`；en-US：`Jul 28, 2026` |
| 时间 | zh-CN：24 小时制；en-US：可选 12 小时制 |
| 数字 / 金额 | 千分位分隔符按 locale 规则 |
| 排序 | 按当前语言排序规则（拼音 / 字母序） |

### 5.4 语言切换交互

**【必须】** 语言切换入口固定于 Shell 全局导航右上角；切换后原地刷新当前路由与滚动位置；`<html lang>` 属性同步更新；已加载插件的语言包**增量合并**而非整体重新加载页面。

## 6. 按需装载与展示规范（插件化加载模型）

### 6.1 加载与激活分离（核心新增）

参考微内核架构，前端加载能力拆分为两个独立职责，避免耦合：

| 组件 | 职责 | 不负责 |
|---|---|---|
| **PluginLoader** | 解析 Bundle（Local Bundle 或受控 Remote Bundle）、创建组件实例 | 不管理生命周期状态 |
| **PluginManager** | 调用 `onActivate` / `onDeactivate`，管理插件启用 / 停用状态 | 不解析 Bundle 内容 |

**【必须】** `onActivate` / `onDeactivate` 必须满足：**幂等**（重复调用不产生副作用）、**超时保护**（超时视为激活失败并隔离）、**故障隔离**（单插件异常不阻塞 Shell 与其他插件）。`onDeactivate` 必须释放事件订阅、定时器、WebSocket、Store watch、路由注册等全部资源。

### 6.2 加载层级与拆分策略（沿用并细化 V1.0）

| 层级 | 策略 | 说明 |
|---|---|---|
| 路由级 | Code Splitting | 仅为已启用插件注册的路由才加载对应 chunk，禁用插件不产生网络请求 |
| 插件级 | 动态导入 + 生命周期分离 | 见 6.1，插件市场未安装的能力不出现在构建产物加载路径中 |
| 子插件级（新增） | 二级按需加载 | 如 `service` 插件下的 MySQL / PostgreSQL / Redis / Kafka / RabbitMQ 子插件，用户进入具体子模块时才加载对应子 Bundle |
| 资源级 | 图片 / 视频懒加载 | 视口外资源使用 `loading="lazy"` 或 IntersectionObserver |
| 数据级 | 按需分批请求 | 列表、图表数据按分页 / 滚动区间请求 |
| 语言包级（新增） | 随插件按需加载 | 见第 5.2 节 |

**【必须】** 首屏仅加载 Shell + 用户当前 tenant/space 下**必须展示**的插件（如 Dashboard），其余插件延迟到用户实际导航触达时加载。

### 6.3 列表与数据展示模式（沿用 V1.0）

| 数据量级 | 推荐模式 |
|---|---|
| < 50 条 | 一次性渲染 |
| 50–500 条 | 分页 Pagination |
| > 500 条 / 信息流 | 无限滚动 + 虚拟列表 |

### 6.4 加载 / 空 / 异常状态（结合插件故障隔离补充）

| 状态 | 展示要求 |
|---|---|
| 加载中 | 骨架屏还原目标内容轮廓，避免位移跳动 |
| 空状态 | 插画 / 图标 + 引导文案 + 可选操作按钮 |
| 加载失败（数据） | 明确错误提示 + 重试按钮 |
| **插件加载 / 激活失败（新增）** | 展示插件级错误边界（Error Boundary），仅隔离该插件区域，不影响 Shell 与其他插件；提供"重试加载"与"反馈"入口 |
| **API 故障且无可信快照（新增）** | 进入最小安全页面（仅 Shell 基础壳 + 提示信息），禁止使用过期或跨身份缓存兜底展示业务菜单 |

## 7. 缓存与性能治理（支撑按需加载）

> 本章为 V2.0 新增，将"按需加载"从前端策略延伸到服务端缓存分层，二者共同决定用户感知的加载速度与数据新鲜度。

### 7.1 分层缓存模型

```text
L1 进程内缓存（前端 Navigation Manager 侧 / 后端服务进程侧）
   ↓ 未命中
L2 共享快照缓存（如 NATS JetStream KV，小对象 / 低频更新 / 可重建）
   ↓ 未命中或校验失败
L3 数据库（权威来源，始终可回源重建 L1 / L2）
```

| 层级 | 默认时效 | 定位 |
|---|---|---|
| L1 进程内缓存 | 约 30 秒 | 降低单实例重复计算 |
| L2 共享快照 | 默认 10 分钟，可配置 5–30 分钟 | 跨实例共享，减少数据库压力；TTL 仅用于清理旧版本与事件遗漏兜底 |
| L3 数据库 | 无 TTL，权威来源 | 任何时候均可重建 L1 / L2 |

**【必须】** 正常情况下的一致性刷新依靠**版本键提升 + 事务性事件发布（Outbox）+ 变更事件通知**，而非依赖 TTL 过期；TTL 只是兜底手段。

**【必须】** 缓存键必须绑定身份与上下文（用户 / 租户 / 空间 / 权限版本），**禁止跨用户、跨租户复用**；仅当权限集合、租户、空间、插件版本完全一致时，才允许按权限集合哈希共享缓存。

### 7.2 缓存容量治理

**【建议】** 明确设定并监控：L1 条目数量上限、共享缓存 Bucket 容量、单值大小上限、键数量与快照年龄指标，防止无界增长。

### 7.3 通用缓存组件的引入边界

**【建议】** 是否引入 Redis 等通用缓存组件遵循"按需引入"原则：仅当出现**高频分布式缓存、原子限流、复杂数据结构（Hash/Set/Sorted Set/Bitmap）或第三方组件强依赖**时，经压测验证后引入；不作为微内核默认依赖，避免为"简单的可重建控制面状态"引入过重的通用缓存中间件。

## 8. 风格切换与设计令牌（Token 契约化）

### 8.1 Design Token 体系（沿用 V1.0）

所有视觉属性（颜色、字体、间距、圆角、阴影、动效时长）均令牌化，禁止组件样式硬编码具体数值。

| Token 分类 | 示例 | 作用 |
|---|---|---|
| 颜色 Color | `--color-primary`，`--color-bg-surface` | 语义化颜色，随主题动态取值 |
| 字体 Typography | `--font-size-body`，`--font-weight-bold` | 统一字号 / 字重阶梯 |
| 间距 Spacing | `--space-md` | 8px 基准网格倍数 |
| 圆角 Radius | `--radius-sm/md/lg` | 4 / 8 / 16px |
| 阴影 Elevation | `--shadow-1 ~ shadow-4` | 表达浮层优先级 |
| 动效 Motion | `--duration-fast` = 120ms | 统一交互反馈节奏 |

### 8.2 新增：Token 作为 Shell 与插件的共享契约

**【必须】** Design Token 与基础组件通过独立共享包（如 `packages/ui-kit`）统一分发，Shell 与全部插件（包含子插件）**必须**引用同一份 Token 包，禁止插件在内部重新声明色板或覆盖全局 CSS 变量。

**【必须】** 主题切换（浅色 / 深色 / 跟随系统）在 Shell 层通过 `data-theme` 属性统一驱动，并通过 **Event Bus** 广播主题变更事件，已加载的插件订阅该事件实时响应，不需要插件自行监听系统主题。

**【建议】** Plugin SDK 对外暴露的组件属性中不接受"自定义颜色值"类 Prop，只接受语义化 Token 名称（如 `variant="danger"` 而非 `color="#F04438"`），从机制上杜绝插件游离于主题体系之外。

### 8.3 主题模式

用户选择需持久化保存，刷新后保持；切换伴随 150–250ms 颜色过渡动效。

## 9. 权限与安全边界

> 本章为 V2.0 新增，明确"界面表现"与"安全边界"的职责分离，防止团队误将前端隐藏当作权限控制。

**【必须】** 前端菜单隐藏、按钮置灰、路由守卫**仅用于改善体验**，一律不构成安全边界；任何写操作 / 敏感读操作的业务 API 必须独立、完整地重新校验权限。

**【必须】** 权限集合具备版本号（`permissionVersion`），版本提升时必须使前端已缓存的导航快照失效并触发刷新，不能依赖用户手动刷新页面。

**【必须】** Shell 侧的 **Permission Store** 只保存服务端返回的权限结果供前端快速判断（如按钮是否置灰），不进行本地权限推导或补充计算。

**【建议】** 高风险操作（删除、批量变更、跨租户操作）除服务端校验外，前端增加二次确认交互，降低误操作概率。

## 10. 多租户与上下文治理

> 本章为 V2.0 新增，源于多租户 / 多空间场景下"半新半旧界面"这一常见但高风险的设计与工程问题。

### 10.1 上下文模型

```typescript
interface AppContext {
  tenantId: string
  spaceId?: string
  environmentId?: string
  clusterId?: string
}
```

**【必须】** 任一上下文字段变化都必须触发**整体**重新计算导航、权限与插件可用状态，禁止仅替换单一字段而遗留旧上下文关联的菜单 / 数据 / 缓存。

### 10.2 原子切换流程

**【必须】** 上下文切换需遵循：

```text
用户发起切换
→ 生成新的 contextGeneration 标识
→ 取消旧上下文下所有进行中的请求（AbortController）
→ 清空导航 / 权限 / 插件状态缓存
→ 重新请求导航与权限
→ 重新挂载受影响的插件区域
→ 丢弃"迟到"的旧上下文响应（按 contextGeneration 校验）
```

**【必须】** 必须防止旧租户的迟到响应覆盖新租户界面状态，所有异步响应处理前需校验其所属 `contextGeneration` 是否为当前值。

### 10.3 插件区域的租户隔离

**【建议】** 插件内部的本地状态（Store、缓存、订阅）应随上下文切换重置，插件在 `onDeactivate` 阶段需完整清理，避免跨租户数据残留在插件内存或本地存储中。
