## 关键修复

升级等待原先只看 `AvailableReplicas`，旧 Pod 仍可用时会把 bad v3 误判为成功。
现改为 `waitRolledOut`：

- `ObservedGeneration >= Generation`；
- `UpdatedReplicas >= desired`；
- `ReadyReplicas >= desired`；
- `AvailableReplicas >= desired`；
- `UnavailableReplicas == 0`；
- 90 秒有界超时。

## 真实失败与恢复

1. 当前 `hnb-app/demo` 为 v2；
2. 尝试升级到不存在的
   `registry.example/missing@sha256:ffff…ffff`；
3. 新 Pod `ImagePullBackOff`，旧 v2 Pod 仍 Running；
4. 升级等待因新 ReplicaSet 未 Ready 而失败，未误报成功；
5. `workload.rollback` 从 bad image 回到 v2：

```text
source_image=registry.example/missing@sha256:ffff…
target_image=hnb-lab/nginx-v2@sha256:2677367a…
data_irreversible=false
backup_ref=lab-backup-v1
generation=4
```

结果：

```text
{"action":"workload.rolledback", ...}
deployment "demo" successfully rolled out
image=hnb-lab/nginx-v2@sha256:2677367a…
PVC demo-data Bound
marker=upgrade-marker-v1
secret-ok
route accepted, gateway programmed, external probe passed
```

恢复后 readiness revision 3：

```text
ready=true
execution=succeeded
observation=FRESH
externalProbe=passed
volume=passed
```

历史 revision 2 的 readiness 仍为：

```text
revision 2 True passed passed
```

两次记录并存，恢复没有覆盖历史 revision。

## 不可逆降级拒绝

