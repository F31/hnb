## Provider 动作

新增 `workload.upgrade`：

输入严格为：

```text
namespace, name, source_image, target_image, expected_uid,
data_compatible, backup_ref
```

校验：

- source/target 必须 `@sha256:`；
- 当前 Deployment UID 必须等于 `expected_uid`；
- 当前 image 必须等于 `source_image`；
- `data_compatible=true`；
- `backup_ref` 非空；
- generation 必须高于已存 generation；更高 generation 拒绝，equal generation 仅 exact replay；
- 只更新 owned Deployment 的镜像并记录 source/target/backup 注释；
- 等待新版本 available，不修改 PVC；
- 缺少兼容声明/备份引用/错误 source 均在写入前拒绝。

## 边界

- v2 镜像为基于 nginx v1 的本地派生镜像，仅用于不同 digest 的升级验证。
- `backup_ref` 是已声明备份点引用；真实备份创建/恢复属于 4.8。
- 升级失败回滚、不可逆迁移拒绝尚未执行，留 4.8。
- `demo`/`demo-http`/`probe-upgrade` 暂留作证据；4.9 处理删除保留。
