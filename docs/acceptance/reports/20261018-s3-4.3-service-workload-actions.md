## 动作

新增 step type：

```text
service.deploy
```

输入严格限定：

- `namespace`
- `name`（Service 名）
- `workload`（关联 Deployment 名）
- `port`（1–65535 规范十进制）

行为：

- 先读取关联 Deployment；不存在或不属于当前 tenant/provider 时不创建 Service；
- Service selector 固定为 `hnb.io/workload=<workload>`，不接收任意 selector/manifest；
- 复用 `hnb.io/managed-by`、tenant/operation/step/idempotency/fencing/attempt 注释；
- 相同 generation + 相同 attempt + 相同 spec 返回 replay；
- 相同 generation 但 spec 不同拒绝；
- 更高 stored generation 返回 `FENCED`；
- 更低 generation 在 logical identity/spec 一致时 CAS 更新；
- 创建/更新冲突最多重试 5 次；
- 缺工作负载、跨租户工作负载、非法端口都不会留下部分 Service。

## 最小目标权限

`deploy/lab/kubernetes-provider-target-rbac.yaml`：

- SA `hnb-app/hnb-provider`
- Role 仅允许 `apps/deployments` 和 core `services` 的
  get/list/watch/create/update/patch/delete
- 无 Secret、Namespace、集群级权限

实机 `kubectl auth can-i`：

```text
create services -n hnb-app      -> yes
update deployments -n hnb-app   -> yes
create services -n default      -> no
get secrets -n hnb-app          -> no
create namespaces               -> no
```
