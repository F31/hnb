## 本轮新发现并处理的安装缺口（须随 5.10 闭环）

1. **admin 种子绑定剥离了 approve/reject/cancel（代码 bug，已修）**：`cmd/apiserver/bootstrap.go` 给 admin 角色声明了 10 个 action，但 binding actions 只种 `{read,list,create,update,delete,execute}`；`ResolvePermissions` 以 binding actions 对角色权限做笛卡尔积覆盖，导致新装环境**任何 Operation 都无法 approve**（403 permission_denied），且把 approve 等补进 binding actions 会产出 100 条快照、超过 64 条上限。修复：binding actions 改为空数组（继承角色全部 action），已实机验证 approve→succeeded。**注意：存量环境需手工 `UPDATE scoped_role_bindings SET actions='{}'` 或重绑**。
2. kind 节点走代理时需注入 `no_proxy` 含 Harbor/集群地址，否则镜像拉取与 API 访问被劫持。
3. containerd 2.x 的 Harbor 信任必须用 `certs.d` hosts.toml，旧 `registry.configs` 写法无效。
4. apiserver 自迁移与手工预迁移抢跑 `users` 表时会失败，需先手工预迁移。
5. `rbac-syncer` 需显式 `db: {}` 段；migrate Job 的 DSN 必须指向 5432。
6. worker 的 provider key 必须是 `kubernetes-provider`（与代码内 providerID 一致），endpoint 必须带 `/v2/steps:execute` 路径。
7. chart 未为目标 default ns 建 executor RBAC：已手工补 `hnb-kubernetes-provider-executor` Role/RoleBinding（apps deployments/replicasets、core services/pods/pvc/secrets/configmaps、gateway httproutes 全动词）。**chart 缺口，应入 chart**。
8. deploy 默认输入引用 `secret_reference=demo-secret`，该 Secret 不存在会导致 Pod FailedMount、provider 等 readiness 挂死至 step 超时（900s）。已手工创建；**默认输入或预检缺口**。
9. WSL 时钟跳变使 60s TTL bootstrap 凭据瞬间过期；worker 重启后 lazy Token()+permanent rejection 不自愈，必须"重签凭据+更新 `hnb-provider-tokens` Secret+重启 worker"三连。
10. 僵尸 step 清理法：`UPDATE operation_steps SET status='failed', last_lease_id=NULL, last_heartbeat_at=NULL`。
