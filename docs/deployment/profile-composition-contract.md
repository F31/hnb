# 统一底座、四档预设与能力组装

Change：`deliver-lightweight-platform-product-loop`。
Requirement：GOV-002、PREADY-002/003/007、PSHAPE-002、PUPG-006。

本文固定产品/实现映射和后续契约断言，不代表全部生命周期已经实现或认证。
部署组件和资源的事实源仍是 `deploy/charts/hnb/overlays` 与固定版本 manifest，
本文不复制组件清单或另建容量数字。

## 四档预设

| 产品名称 | 现有配置/锁标识 | 默认 overlay 叠加 | 定位 | 功能目录 |
|---|---|---|---|---|
| Minimal | `Minimal` | `minimal.yaml` | 演示/评估，默认单实例、不承诺 HA | 全部已发布能力，按实际条件选装 |
| Lite | `LiteHA` | Minimal + `lite-ha.yaml` | 最小生产的推荐拓扑与保障目标 | 同一目录 |
| Standard | `StandardHA` | Lite + `standard-ha.yaml` | 常用生产容量及维护余量 | 同一目录 |
| Pro | `Enterprise` | Standard + `enterprise.yaml` | 高级/企业场景的推荐组合和保障目标 | 同一目录，不强制全装 |

名称不是认证。当前真实 HA/容量证据仍见 `docs/acceptance/registry.yaml` 和两个依赖
change 的未完成演练；增加副本或 `controlPlaneDomains` 声明不构成已达生产目标。
Startup 是未认证的稀疏初始组合，不是第五档，也不能自动冒充完整 Minimal。

## 不同维度分别保存

| 维度 | 表达内容 | 不能替代什么 |
|---|---|---|
| `releaseVersion` / release lock | Core、Chart、组件与迁移的固定发布 | 不能代替已通过认证 |
| `profile` | 推荐拓扑、默认容量与保障预设 | 不能作为功能许可或可选组件白名单 |
| 组合/已选能力 | 模板、实际选择、能力版本和依赖闭包 | 不能由 profile 默认列表反推用户全部选择 |
| backing/资源绑定 | bundled、in-cluster-ha、external、PVC/外部引用 | 不能只改名称就迁移数据 |
| 权限与证据 | 谁可操作、哪些动作/组合已通过验证 | 目录可发现不意味着已授权或已就绪 |

T0/T1/T2/T3 定义交付基线、默认性、成熟度及认证条件，不是四档功能授权。
相同发布的相同组件版本共用实现、协议与摘要，允许角色/配置/拓扑差异。

## API / CLI / UI 共用的断言

1. 任一档位可以发现并申请安装全部已发布能力；权限、版本、资源、controller、
   目标/站点和 Conformance 不满足时返回具体缺口，不能仅回答“请先升级 Pro”。
2. 目录区分未安装、已安装、已启用、缺依赖、不兼容；未安装的业务菜单仍按
   UX-001 隐藏，权限与能力条件在服务端再次检查。
3. 加载能力不自动改档、不自动获得 HA/生产认证；Pro 也不隐式全装 Pack。
4. 增量规划使用受信配置、锁、run 和观测核对出的当前实际安装态。
   `target = target required baseline ∪ retained selections ∪ explicit additions`。
5. 普通升档保留已选能力、兼容覆写、已调高资源、身份和数据；组件版本由目标发布
   兼容求解，不能盲目保留旧二进制，也不能静默删能力、重置配置或更换存储。
6. 计划固定源状态摘要和目标锁。执行前漂移、未知能力、无兼容解、迁移/证据条件
   缺失时停止并解释，不覆盖并发用户变更。
7. 同档加能力、档位演进和软件 A→B 是三种请求；都不要求更换内核或重装平台。
   卸载/缩容/降级单独显式规划，数据默认保留。
8. 平滑表示原实例增量、保留配置数据、幂等续跑及业务验证；HA 路径优先滚动，
   单实例切换等明确维护窗口，不用未验证的“零停机”代替实际保障。

## 必须验证的矩阵

| 场景 | 预期 | 对应任务 |
|---|---|---|
| Minimal 与 Pro 加载同一组件版本 | 相同实现/摘要/契约，不同配置可见 | 6.10 |
| Minimal 加载已有可选能力 | 条件满足则允许，不更改档位或生产资格 | 6.2/6.10 |
| Lite 选择缺外部依赖的能力 | 返回依赖/容量/兼容缺口，不以 Pro 名义放行 | 6.2/6.10 |
| Minimal + 能力 X 升 Lite | X 和兼容覆写保留，补齐实际目标保障 | 5.3–5.6/7.9 |
| 同档 release A→B，X 没有兼容版本 | 规划阻断，不静默卸载 X | 5.4/5.6 |
| 升级计划后修改配置/选择 | 执行前拒绝失效计划 | 5.5/5.6 |
| 升级中断后续跑 | 不重复初始化身份/目标/资源，复验数据与业务 | 5.8/7.9 |

矩阵状态和证据按实际版本登记。当前 `profilespec.go` 的预设/向量与单调性检查可复用，
但完整实际安装态合成、能力版本求解及执行前漂移保护属于本 change 待实现任务，
不能仅凭已有预设 parity 测试将上表勾为通过。
