# 自研容器平台 2.1 设计方案
## Kamaji + CAPI 统一多模式集群管理平台（整合版）

版本：v2.1 | 日期：2026-10-15 | 变更：整合差异化能力评审意见，能力项从 7 项扩至 10 项

---

# 1. 设计目标与原则

以最小化 Kubernetes 1.37 发行版为底座，同时支持 **HCP 托管、传统 CAPI、独立集群纳管**三种模式。差异化策略：**不重复大厂已商品化的能力**（RBAC/日志/监控/基础多集群纳管），而是利用 K8s 1.30+ 新特性窗口，在 AI 算力、硬隔离、FinOps、IDP 四个方向做出深度。

五条原则：单一声明式入口；管理集群只编排不承载业务；分发版中立；数据面统一（全部差异化能力的根基）；Alpha 特性开关化。

# 3. 管理集群设计

| 项 | 决策 |
|---|---|
| 发行版 | k0s，3 控制面节点 HA，控制面组件专用节点池 |
| HCP | Kamaji operator + Kamaji CAPI Provider（单一 Provider 策略） |
| 数据存储 | CloudNativePG 管理的 PostgreSQL（Kamaji kine 后端），HA + PITR |
| CNI | Cilium + ClusterMesh（东西向）；1.37 已废弃 ipvs |
| GitOps / 证书 | Flux CD / cert-manager |
| 准入策略 | VAP（CEL，高频校验）+ Kyverno（变更策略/例外流程），分工不互替 |

加固：每租户命名空间 ResourceQuota + LimitRange + PDB + PriorityClass；管理集群 etcd 备份 RPO≤1h/RTO≤2h + 季度恢复演练；PG cert 认证 + 每租户独立 database。

# 4. 统一资源模型与三种集群模式

ClusterClass + clusterctl 模板（阶段一建设）。

- HCP：`Cluster` + `KamajiControlPlane` + `MachineDeployment`；传统：`KubeadmControlPlane`；全生命周期 CAPI 编排；
- 独立纳管：自研 `ClusterInventory` CRD + kubeconfig Secret，只读监控 + kubeconfig 分发，不承诺升级/伸缩；
- Bootstrap：默认 kubeadm 流程（与 Kamaji provider 原生契合）；Talos 为阶段零 PoC 结论项；
- 基础设施 Provider：CAPV / CAPO / Metal3。

# 5. HCP 数据面（PostgreSQL）

kamaji-etcd 关闭；DataStore CR `driver: PostgreSQL`；CloudNativePG 提供 HA PG；operator 级默认 + TCP 级覆盖分池；cert-manager 客户端证书认证；普通租户共享实例（kine 表级隔离），大客户独立 DataStore/PG 实例；关注 kine 表膨胀与 vacuum；PITR 备份；与 etcd 路径做写 QPS 基准后定分池策略。

**数据存储升级 = 最高危变更**：独立窗口、租户分批、强制快照、回滚预案，不与应用发布合并。

# 6. 网络

控制面→工作节点 Konnectivity 隧道；租户 API 入口 Gateway/Envoy TLS passthrough（SNI 路由），起步共享入口，关键租户 per-tenant 代理；cert-manager + DNS 自动化；CIDR 走 CAPI in-cluster IPAM；东西向 Cilium ClusterMesh + NetworkPolicy。

# 7. 多租户：软隔离 + 硬隔离双轨模型

**软隔离（默认）**：命名空间 + RBAC + 三层配额（ResourceQuota → 联邦配额 → 租户预算）。

**硬隔离（合规市场，新增）**：
- **创建即安全**：租户命名空间创建时由 Hardening Controller 自动注入基线——VAP 校验策略（CEL，零 Webhook 延迟）+ Kyverno 生成策略（NetworkPolicy 默认拒绝、受限 SecurityContext、ResourceQuota）；
- **专属节点池**：高安全租户分配独立节点池 + 节点标签级出口流量识别与控制；
- **硬隔离边界判断矩阵（平台内置决策能力）**：租户 SLA 声明"跨租户泄露=安全事件"→ 平台强制分配独立集群（HCP 独立 TCP 或传统集群），而非共享集群命名空间；控制台展示每租户隔离级别与合规状态。

# 8. 十大差异化能力（按优先级）

## 8.1 AI 算力治理 ★P0 战略投入
- 基座：DRA 扩展资源 GA、device taints Stable、NUMA 属性 Stable（1.37）；CompositePodGroup（Alpha，实验开关）；
- **设备级运维**：单 GPU 设备污点/下线维护，不波及节点其他设备——超越 Device Plugin 静态分配的关键差异点；
- **GPU 共享与可消耗容量（Consumable Capacity）**：单卡分片、小数配额精细分配，推理场景利用率提升核心；
- 调度：训练 gang scheduling（Volcano/HAMi 作为可选增强调度器）；推理服务 scale-to-zero（联动 8.3）；
- 商业：按团队配额、按卡时计费（对接 8.4 数据面）；差异化价值=AI 团队无需维护独立基础设施孤岛。

## 8.2 无重启资源自治 ★核心壁垒
In-Place Resize（GA）+ VPA InPlaceOrRecreate；1.37 resize 调度器抢占为 Alpha（实验开关）。闭环：用量采集（metrics.k8s.io GA）→ 建议 → 原地调整，零重启；与 8.1 联动（AI 负载突发扩容优先抢占低优先级负载）。

## 8.3 环境自动休眠与唤醒 ★快速见效
HPA scale-to-zero（1.37 Beta 默认开启）。dev/test/预览环境闲置自动归零、请求唤醒；HCP 集群休眠控制面 Pod（PG 存储无快照重启）；目标回收 30%+ 闲置算力。

## 8.4 FinOps 预算感知治理 ★CFO 视角
- 容器级成本分摊（OpenCost，Pod/命名空间/标签维度，而非 VM 维度）；
- 跨集群统一成本视图 + **异常检测**（突增告警）；
- **成本感知调度**：性能达标前提下优先调度至低成本节点池；
- **预算准入**：自研 Budget Controller，租户预算（货币维度，跨集群联邦）超限时新负载排队/降配/转 spot，而非直接失败。

## 8.5 敌意多租户硬隔离 ★合规市场钥匙
见第 7 节：创建即安全、专属节点池+出口控制、硬隔离边界判断矩阵。与 8.8 组成金融/医疗/政务合规矩阵。

## 8.6 平台金丝雀升级
canary 集群先行 → 健康度指标达标 → 批次推进 → 异常自动暂停；覆盖 K8s 小版本、节点 OS（不可变 OS 原地替换）、Kamaji operator 升级。

## 8.7 零信任工作负载身份
Pod Certificates + Cluster Trust Bundles（1.37 Stable）：免 sidecar 短周期自动轮转 mTLS，面向等保客户。

## 8.8 审计证据自动化
CIS Benchmark 持续扫描 + 配置漂移检测 + 等保/SOC2 证据包自动生成，覆盖三模式集群（Fleet Controller 数据面）。

## 8.9 IDP 开发者平台 ★产品化关键
- 黄金路径模板：Web 服务/批处理/AI 推理三类预配置模板（网络/存储/安全/可观测最佳实践默认值）；
- 自服务集群供给：Git PR 申请 → CAPI/HCP 自动供给（与阶段一架构天然复用）；
- Backstage 门户：平台能力目录化，隐藏底层 K8s 复杂度；以 DORA 指标度量平台价值。

## 8.10 舰队联邦与边缘
- **Karmada**：PropagationPolicy/OverridePolicy 跨集群工作负载分发（如按区域覆盖镜像仓库地址）；与 ClusterMesh 分工——Karmada 管工作负载，ClusterMesh 管网络；
- **OCM Pull 模型**：边缘/受限网络集群主动拉取配置，避免中心主动连接；
- 边缘轻量发行版 k0s/k3s 接入，版本一致性由管理集群统一编排。

# 9. 横切能力

可观测（集中采集 HCP/PG/kine/CAPI 指标 + Hubble 流日志）；供应链安全（cosign 准入 + Tetragon 运行时 + External Secrets）；备份（PG PITR、etcd 快照 + Velero、季度恢复演练）；版本治理（Kamaji edge 锁 digest + 内网镜像 + 金丝雀升级）。

# 10. 可选模块：KubeVirt VM 统一管理（独立评估，不进核心架构）

价值真实（VMware 迁移潮、VM/容器长期共存），但属独立产品线级投入。有利条件：CAPI 已有 KubeVirt provider（CAPK），与统一资源模型兼容；KubeVirt 集群可作为第四种集群模式挂载。建议：待核心三模式稳定后（阶段三末）以独立立项评估，不与本期承诺绑定。

# 11. 风险清单（Top）

| 风险 | 缓解 |
|---|---|
| Kamaji 无 stable 版本线 | digest 锁定 + 内网镜像 + 金丝雀升级 |
| PG 数据存储升级爆炸半径 | 最高危变更独立编排，租户分批，强制快照 |
| Talos bootstrap 兼容性 | 阶段零 PoC 定论；默认 kubeadm 流程 |
| 共享 API 入口单点 | 关键租户 per-tenant 代理选项；入口多副本 |
| Alpha 特性回退（resize 抢占/CompositePodGroup） | 全开关化，默认关闭，升级前兼容性检查 |
| 能力面扩张风险（10 项差异化） | 按 12 节优先级排期，P1 快速见效项先行，不并行铺开 |

| 阶段三：差异化深化 | 持续 | 8.2 资源自治 → **8.5/8.8 硬隔离+审计（合规线打包）** → 8.6 金丝雀升级 → 8.7 → **8.9 IDP** → 8.1 AI 算力（视战略）→ 8.10 联邦边缘（按需） |

# 13. 技术决策汇总

| 决策点 | 结论 |
|---|---|
| HCP Provider | Kamaji 单选；edge release 自建治理（锁 digest/内网镜像/金丝雀） |
| 数据存储 | CloudNativePG（PostgreSQL），cert 认证，分池隔离 |
| 引导 | kubeadm 默认；Talos 阶段零定论 |
| 准入策略 | VAP（CEL 校验）+ Kyverno（生成/例外）分工 |
| 多租户 | 软隔离默认 + 硬隔离判断矩阵（独立集群强制项） |
| GPU | DRA Consumable Capacity + device taints + Volcano/HAMi 可选 |
| 联邦 | Karmada（工作负载）+ ClusterMesh（网络）分工；边缘 OCM Pull |
| 集群模板 | ClusterClass + clusterctl |
| 开发者面 | 黄金路径模板 + Backstage + PR 自服务集群 |
| KubeVirt | 可选模块，独立立项评估，不进核心架构 |
